# CSR-BUILD — Alembee by CSR Build Control

This private repository is the independent build-control home for Alembee by CSR. It contains the cross-repository execution baseline derived from the Curtis Doctrine corpus and connected repository estate.

Runtime and donor code remains in its own repositories. `CSR-BUILD` controls scope, traceability, dependencies, migrations, acceptance gates, evidence and release coordination; it does not silently transfer source ownership or collapse the repositories into one codebase.

Read in this order:

1. [`PRODUCT_CONSTITUTION.md`](./PRODUCT_CONSTITUTION.md) — non-negotiable doctrine.
2. [`PLAN_SOT.md`](./PLAN_SOT.md) — controlling product and architecture plan.
3. [`IMPLEMENTATION_PLAN.md`](./IMPLEMENTATION_PLAN.md) — W0–W8 execution, epics and done gates.
4. [`REPOSITORY_EVIDENCE_BASELINE.md`](./REPOSITORY_EVIDENCE_BASELINE.md) — what the connected source currently proves and does not prove.
5. [`CROSS_REPOSITORY_HANDOVER.md`](./CROSS_REPOSITORY_HANDOVER.md) — contracts, authority and integration order.
6. [`TRACEABILITY_MATRIX.md`](./TRACEABILITY_MATRIX.md) — corpus/source coverage.
7. [`OPEN_OBJECT_REGISTER.md`](./OPEN_OBJECT_REGISTER.md) — decisions and evidence required before named implementation/release steps.
8. [`CAPABILITY_AND_USE_CASE_SPEC.md`](./CAPABILITY_AND_USE_CASE_SPEC.md) — full user, operator, commercial and agentic capability catalogue.
9. [`ACCEPTANCE_TEST_CATALOGUE.md`](./ACCEPTANCE_TEST_CATALOGUE.md) — positive, negative and promotion conformance suites.
10. [`MIGRATION_AND_CUTOVER_PLAN.md`](./MIGRATION_AND_CUTOVER_PLAN.md) — source transformation, data migration, shadowing, cutover and rollback.

The package does not begin feature development and does not certify implementation. It establishes PD0 planning control so the repository can be transformed without losing corpus intent, donor provenance, authority boundaries or release evidence.
